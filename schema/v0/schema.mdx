Every line of a connection is one JSON object: the [envelope](#envelope) plus the fields of its message type, selected by `t`. This page is generated from the same source as the [JSON Schema](https://agentwireprotocol.com/schema/v0/awp.schema.json) (draft 2020-12), the `wire` package of the reference implementation, and lists the same constraints. Where it disagrees with [the specification](https://agentwireprotocol.com/spec), the specification wins and the schema has a bug.

Receivers ignore fields they do not know, and lines whose `t` they do not know, so no object here is closed. Messages marked *extension* are spoken by the reference implementation and not in the specification.

## Envelope

Envelope holds the fields every line carries (section 6). The type-specific fields sit beside them at the top level.

| Field | Type | Required | Description |
|---|---|---|---|
| `t` | string | yes | `t` is the message type. |
| `id` | string, non-empty | yes | `id` is unique per sender. A ULID or UUIDv7 is recommended, so that ids sort by time; resume compares ids as strings. |
| `ts` | string, date-time | yes | `ts` is an RFC 3339 UTC timestamp. |
| `th` | string |  | `th` is the thread id. Required for msg, state and ack. |
| `re` | string |  | `re` is the id of the message this one responds to. |

Unknown fields are ignored; unknown types are ignored too, after reading the envelope.

## Messages

Each message carries the envelope; the tables list the fields beside it.

### hello

Hello is the first line each side sends, at once, without waiting for the other (section 7.1).

Envelope: `t` is `"hello"`.

| Field | Type | Required | Description |
|---|---|---|---|
| `v` | integer, ≥ 0 | yes | `v` is the protocol major version. A peer that sees a version it does not speak sends err version and closes. |
| `key` | string, `^ed25519:[A-Za-z0-9_-]{43}$` | yes | `key` is the long-term Ed25519 public key. Its bytes are the peer's identity. |
| `name` | string |  | `name` is how the peer calls itself, "harness@host" by convention. |
| `nonce` | string, `^[A-Za-z0-9_-]+$` | yes | `nonce` is 32 random bytes, base64url. The auth signature covers the whole hello line, nonce included. |
| `caps` | array of string |  | `caps` lists the supported message families beyond the mandatory chat and resume: blob, grant, introduce, and any extension. |
| `about` | string |  | `about` is free text for the other agent's context. It is not authenticated until auth completes. |
| `addr` | string |  | `addr` is an extension: an address at which the sender can be reached, so that either side can reconnect (section 4.3). Peers that do not know it ignore it, as section 5 requires. |
| `shares` | array of string |  | `shares` is an extension (mirror.go): the keys of the hosts this agent mirrors its conversations to, so the other party knows. |

### auth

Auth proves possession of the key sent in hello (section 7.2).

Envelope: `t` is `"auth"`.

| Field | Type | Required | Description |
|---|---|---|---|

### resume

Resume is sent by both sides after every handshake (section 9.5). The receiver replays its outbox messages the sender has not seen.

Envelope: `t` is `"resume"`.

| Field | Type | Required | Description |
|---|---|---|---|
| `seen` | object of string | yes | `seen` maps each thread id to the last message id the sender has durably received in it. Empty on a first connection. |

### state

| Field | Type | Required | Description |
|---|---|---|---|
| `state` | string | yes | `state` is the thread state: open, working, waiting, done, failed or closed by convention; peers may use others. |

### msg

Msg is one turn in a thread (section 9.1). The first msg with a new th creates the thread.

Envelope: `t` is `"msg"`; `th` is required.

| Field | Type | Required | Description |
|---|---|---|---|
| `subject` | string |  | `subject` is the thread's title, meaningful on its first message. |

### ack

Ack says the msg or state named by re is durably received (section 9.2). Acks drive outbox pruning and are not acked themselves.

Envelope: `t` is `"ack"`; `th` and `re` are required.

### chunk

Chunk carries part of a blob (section 9.3). Chunks of one blob arrive in order; chunks of different blobs may interleave. A chunk carries th when the blob belongs to a thread, so that resume replays it like any other threaded message.

Envelope: `t` is `"chunk"`.

| Field | Type | Required | Description |
|---|---|---|---|
| `ref` | string | yes | `ref` names the blob, as the sender chose it. |
| `n` | integer, ≥ 0 | yes | `n` is the chunk index, from 0. |
| `last` | boolean | yes | `last` is true on the final chunk. |
| `data` | string, `^[A-Za-z0-9+/]*={0,2}$` | yes | `data` is the chunk's bytes, standard base64 (B64Pattern; the tag syntax cannot carry the padding). |

### ping

Ping is a liveness probe (section 9.4): sent when idle for 30 seconds by convention; two missed pongs mean the connection is dead.

Envelope: `t` is `"ping"`.

### pong

Pong answers a ping; re names the ping.

Envelope: `t` is `"pong"`; `re` is required.

### bye

Bye is a graceful close (section 9.6). After sending it a peer sends nothing else and closes after the other side's bye or after 5 seconds.

Envelope: `t` is `"bye"`.

|---|---|---|---|
| `reason` | string |  | `reason` says why, for the log. |

Envelope: `t` is `"err"`.

### presence

*Extension.* PresenceMsg is an extension: it carries one signed presence document, gossiped to every peer that lists presence in its hello caps. Doc travels unchanged from relay to relay; the envelope and Hops are per hop.

Envelope: `t` is `"presence"`.

| Field | Type | Required | Description |

| `of_name` | string |  | `of_name` is the other party's name. |

*Extension.* Private is an extension: it asks the receiver to keep the thread th out of what it shares with its hosts, and those hosts to forget it.

## Objects

Objects carried inside messages.

### Grant object

GrantObject is the wire form of a grant (section 10.2): a signed statement that sub may use caps until exp, honored by iss and by whoever trusts iss. sig is iss's Ed25519 signature over the canonical JSON of the object without sig: keys sorted, no whitespace, UTF-8.

| Field | Type | Required | Description |
|---|---|---|---|
| `iss` | string, `^ed25519:[A-Za-z0-9_-]{43}$` | yes | `iss` is the granting key. |
| `sub` | string, `^ed25519:[A-Za-z0-9_-]{43}$` | yes | `sub` is the receiving key. |
| `caps` | array of string | yes | `caps` are the capability strings granted (section 10.1). |
| `exp` | string, date-time | yes | `exp` is when the grant expires, RFC 3339. |
| `nonce` | string, `^[A-Za-z0-9_-]+$` | yes | `nonce` makes each grant distinct, base64url. |
| `sig` | string, `^[A-Za-z0-9_-]+$` | yes | `sig` is the issuer's signature, base64url. |
| `aud` | string, `^ed25519:[A-Za-z0-9_-]{43}$` |  | `aud` is an extension: when set, only the peer with this key should honor the grant. Introductions use it so that a grant meant for the introduced peer does not also give the recipient powers over the introducer. Peers that do not know the field ignore it, which can only make them honor less, never more, than the spec already says. |
